A caller can deliberately reuse another user's known transfer ID, and any collision makes callback settlement ambiguous: a signed success/failure callback may settle the wrong user's wallet. Generate a server-side globally unique transfer ID (or namespace it with the authenticated UID) and store an unambiguous callback mapping; retain the client request ID only for per-user idempotency.
